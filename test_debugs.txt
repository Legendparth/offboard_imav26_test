Two ways to be sure you're on the new code once it starts: the traceback line publish_frames ... self.bridge.cv2_to_imgmsg cannot occur (that line is now self.image_pub.publish(array_to_imgmsg(...))), and ros2 topic hz /window_detection/image will show frames flowing.

Keeping numpy<2 is still the right call for the rest of the ROS Python stack on that machine, but window_detect no longer depends on it either way — 1280x720 frames from /zed/zed_node/rgb/color/rect/image were decoding fine in that log, so once the stale install is gone you should get detections straight away.
